# Story Master｜Visual Narrative Continuity

## Purpose
本 Reference 只处理 Story Master“完整故事”中关键剧情节点之间的叙事跳步，让未参与前期设计的编剧、绘本作者或动画导演仅阅读正文，就能连续理解事件如何发生。它不修改 Story Lock、冻结设定、角色动力、解决方案或媒介边界。

## 1. Five Continuities
- **Space Continuity**：人物、场景与关键物体的位置和出现来源清楚。
- **Action Continuity**：首次关键动作包含理解下一状态所需的步骤。
- **Causal Continuity**：“感知 A → 想到 B → 执行 C”的连接存在。
- **Object State Continuity**：关键物体进入、改变、使用与结果的状态连续。
- **Intention Continuity**：角色此刻采取行动的原因可以理解。

## 2. Production Rules
1. **R1**：陌生下游能够连续复原关键行动链。
2. **R2**：先确认是否真的存在连续性缺口，再决定是否增加文字。
3. **R3**：首次关键行动与首次解决方案执行采用最低充分颗粒度；建立后的重复动作可以压缩。
4. **R4**：角色改变办法之前必须出现可看见、听见、摸到或试出的依据。
5. **R5**：解决方案依赖的关键物体必须保持状态连续。
6. **R6**：解决方案必须有可见结果证明有效，不能只宣布“成功”。
7. **R7**：认知可以简单，事件过程必须清楚。

## 3. Minimum Sufficient Granularity
关键行动链应能被连续理解：
> 人物与物体在哪里 → 发生什么变化 → 角色感知到什么 → 为什么改变行动 → 第一次怎样执行 → 产生什么可见结果
这是一项内部写作检查，不是输出模板，也不要求正文逐项回答。

每个主要 Story Beat 按实际需要检查十类信息：场景状态、角色当下目标与注意力、重要动作过程、可见结果、角色反应、关系动作、感官锚点、情绪推进、转场逻辑、结尾 Payoff。它们用于发现缺口，不是要求每段机械填满十项。

结构化 Story Lock、场景顺序表、Emotion Curve、Visual Anchors 或 Adaptation Notes 只能辅助正文，不能替代正文中的关键剧情事实。若只有查看附录才能理解故事，`STORY_INFORMATION_SUFFICIENCY = FAIL`。

## 4. Object State Ledger

对承担因果作用的关键物体，在最终正文装配后做一次轻量状态账本。至少追踪：

```text
IDENTITY
QUANTITY
LOCATION
COMPOSITION
VISIBLE_STATE
OWNER_OR_HOLDER
USED_OR_UNUSED
CHANGED_BY
CHANGE_EVENT
```

规则：

1. 状态只能由正文中明确发生的事件改变。
2. “画面以后可以解释”不能补救正文里没有发生的状态变化。
3. 附录、场景表或 Visual Anchor 不能创造正文不存在的四块 / 两组 / 新成分 / 新位置。
4. 如果前文建立“A 与 B 状态相同”，后文要出现差异，必须存在生成差异的可追踪事件。
5. 角色感知错误可以存在，但叙事事实本身不能自相矛盾；若是角色误判，应明确这是人物判断而不是客观状态。

任何关键状态跳变找不到 `CHANGE_EVENT`：

```text
OBJECT_STATE_CONTINUITY = FAIL
```

## 5. Compression Boundary
### 可以压缩
- 已经完整建立过的重复动作；
- 不影响理解的移动；
- 后续相同操作；
- 无因果价值的装饰动作。

### 不得压缩
- 首次关键动作；
- 促使角色改变办法的关键观察；
- 关键道具首次进入解决方案；
- 解决方案第一次完整执行；
- 证明方案有效的结果；
- 删除后会迫使下游自行发明因果的信息。

> “由画面承担”不等于“Story Master 可以不定义发生了什么”。
画面可以选择表现方式，Story Master 仍须定义事件事实、关键因果与可见结果。

## 6. Do Not Overwrite
不得为了应用本 Reference 而：
- 逐帧描述动作；
- 规定固定动作数量或固定字数；
- 为每件道具说明精确尺寸；
- 为每次移动写完整路线；
- 写成分镜脚本或操作说明书；
- 统一扩写所有故事；
- 修改原本已经连续清楚的段落。

核心判断：只补“不写就需要下游猜”的信息。

### SHOW_ONCE, EXPLAIN_ONLY_IF_NEEDED

当一个关键关系已经通过人物动作、物体状态、停顿、声音或结果被清楚表现后，不再用对白或旁白重复解释同一信息。

首次关键行动应完整建立；一旦读者已经理解规则如何运作，后续同类行动立即进入压缩。“连续性完整”不等于“解释完整”，优先让行动承担信息。

禁止：
- 多名角色连续解释同一个解决方案；
- 动作已经证明之后再总结操作规则；
- 在故事正文中写入编辑式元叙述；
- 为了“让读者明白”而重复已经可见的信息。

**BAD：**角色完整完成一次交接后，三个人又分别解释“先听完”“再交木牌”“最后拍一下”，旁白再总结轮流规则。

**GOOD：**上一位说完 → 邀请下一位 → 木牌交稳 → 小熊轻轻敲一下 → 下一位开始。随后只写：“木牌沿着小圈继续传下去。”

动作已经建立规则，不需要再解释一遍。

## 7. Minimal Continuity Example
**BAD：**几片纸叶被风吹散了。小熊拿来篮子，大家很快把叶子收好了。

问题：节点正确，但缺少从观察到办法、选择工具、第一次执行与结果验证的必要连接。

**GOOD：**小兔发现纸叶在光滑地面上一直往前滑，碰到粗糙地垫时却慢了下来。小熊因此想到把篮子放到地垫边；两人先试着放进去一片，纸叶没有再滑走。确认办法有效后，他们才继续收拾。

GOOD 只补必要桥梁，不规定逐帧动作、精确距离或镜头表达。
